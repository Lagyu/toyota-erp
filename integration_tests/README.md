# Integration tests

Contract tests of the running API against the committed OpenAPI document
(`apps/automotive_core/automotive_core/integration_hub/openapi.json`, generated by
`scripts/dev/openapi.py` and kept current by lint). They check:

- every documented method exists, and refuses guests with the documented 403;
- every read without required parameters answers with a documented status, and a 200 body
  matches its response schema;
- the signed inbound endpoint answers unsigned, unknown and badly signed deliveries with 401;
- with the run's personas (`INTEGRATION_CREDENTIALS`, set by `scripts/ci/e2e.sh`): every
  method that names the roles it requires refuses a line operator without them and a partner
  portal user, every partner-portal method refuses the other kind of partner, and a Kyushu
  user's lists and reads hold no Aichi documents (`test_authorization.py`); concurrent
  requests to critical workflows create one document (`test_concurrency.py`).

They use only the Python standard library and run from the host against a site that serves
the API:

```bash
./scripts/ci/contract.sh --url http://127.0.0.1:18000 --site small.localhost
./scripts/ci/contract.sh --url https://erp.example --password-file /etc/hinode/secrets/admin_password
```

The cross-application business tests that need the application's code (journeys over
several apps) live in the apps' own test packages, e.g.
`apps/automotive_supply_chain/automotive_supply_chain/tests/test_journeys.py`, and the browser
journeys in [`e2e/`](../e2e/).
